# 5.0.5

This release makes rendering faster and fixes several element props, stores that return unusual values, and the Vite plugin when Dolla is linked into an app.

## Fixes

- **`list` and `form` props no longer throw.** `<input list="options">` and `<button form="signup">` failed while mounting with "Cannot set property list … which has only a getter".
- **`width` and `height` keep values such as `100%`.** On images and other elements where the DOM property is a number, `width="100%"` was rendered as `width="0"`.
- **`draggable`, `spellcheck` and `translate` can be turned off.** Passing `false` removed the attribute, which left the browser's default in place, so an image stayed draggable and a text field kept its spell check. They are now written as `draggable="false"`, `spellcheck="false"` and `translate="no"`.
- **`hidden="until-found"` keeps its value.** It was rendered as plain `hidden`.
- **Content inside `<foreignObject>` renders.** The element was created as an HTML element inside its `<svg>`, and browsers show nothing inside that. See [SVG](../templates.md#svg).
- **A store can return any value.** `addStore` threw when a store returned a frozen object, or a primitive such as a number or a string. A store that returns nothing can now be read with `getStore`, which reported it as not provided. Its cleanup hooks also run after a hot reload of the view that provides it, which they didn't before.
- **The Vite plugin works when Dolla is linked.** With Dolla linked into an app (`npm link`, `bun link`, a workspace), the app failed on startup with a `TypeError` from the HMR runtime, or started and never applied a hot update. See [Setup](../hmr.md#setup).

The rules for which props are set as attributes are in [Text and attributes](../templates.md#text-and-attributes).

## Improvements

Timings are script time in headless Chromium, compared with 5.0.4.

- **Elements mount and unmount faster.** An element no longer gets a context of its own unless it needs one. Creating 10,000 table rows went from about 125 ms to 55 ms, mounting elements nested 40 deep is more than twice as fast, and unmounting 15,000 small views went from about 24 ms to 12 ms.
- **Clearing a list is about twice as fast.** `repeat` removes its rows from the page in one step instead of one at a time: clearing 10,000 rows went from about 100 ms to 52 ms. Updates that don't reorder the items also do less work.
- **`html` templates are parsed once.** Later calls only fill in the values, which makes a call about 15 times faster. Mounting 5,000 rows written with `html` went from about 28 ms to 12 ms.
- **Number, date and list formatting in translations is much faster.** The `number`, `datetime` and `list` formatters reuse their `Intl` formatter instead of building one for every value, which took 8 µs for a number and 26 µs for a date.
- **A `class` given as a getter that returns a string updates faster.**
- **Signals update up to 30% faster** in apps that mix named and unnamed computed values and effects.
- **JSX fragments cost nothing.** `<>...</>` no longer creates a view and a context.
- **Appending to a long virtual list is faster.** Measured heights are kept when the existing items stay where they are. Appending to 100,000 items went from about 5 ms to 0.5 ms.

## Behavior changes

- **`width` and `height` are always set as attributes on HTML elements.** Use `prop:width` to assign the DOM property instead.
- **Clearing a `repeat` list removes everything between its first and last item.** A node that other code inserted among the list's items is removed with them.
- **In debug mode, elements inside a fragment show the view around them in `data-view`.** They showed `Fragment`.

## Internal API changes

These only affect code that uses `@manyducks.co/dolla/internals`.

- **`hasStore` returns `true` for a store that was added and returned `null` or nothing.** It returned `false`.
- **An `ElementNode` shares its parent's context** unless it enters or leaves SVG or has a CSS template attached. Code that passed a context to an element and expected its children to get a new one now sees the same context.

## Upgrading

Update the package. The Vite plugin and the HMR runtime ship together and should be the same version. No code changes are needed.

If you link a local copy of Dolla into an app, check that the whole app resolves to that copy. A second copy left in a nested `node_modules` runs as a separate Dolla.
