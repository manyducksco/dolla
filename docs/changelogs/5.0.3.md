# 5.0.3

Everything in this release affects development with hot module replacement only. Production builds are unchanged.

## Features

- **CSS templates hot reload in place.** Editing a `css` template declared at the top level of a module restyles every element that uses it, including in modules that import it, without re-running any views, so their state is kept. See [CSS templates](../hmr.md#css-templates).
- **Warning for import cycles that re-mount the app.** When an edit re-runs the module that calls `createRoot` because they're in an import cycle, the Vite plugin logs the chain and the import that closes it. See [Import cycles](../hmr.md#import-cycles).

## Fixes

- **Effects in hot-replaced views wait for their elements.** Effects in a view replaced by a hot update, and in the views under it, ran before their elements were rendered, so an effect reading a ref threw on every edit to an ancestor's file.
- **Private stores keep working after their module reloads.** A store kept private behind exported helpers (`addAuth` and `getAuth` around `function AuthStore`) failed with "Store is not provided by this context" after a hot update. See [Stores](../hmr.md#stores).
- **Stores keep their identity through import cycles.** A store used by a reloaded module before that module finished evaluating no longer gets a separate identity.

## Upgrading

Update the package. The Vite plugin and the HMR runtime both ship in it and must be the same version, since the plugin now generates imports the older runtime doesn't have.
